TEST - 项目测试文档
1. 文档概述
本文档依据 spec.md 开发规范、requirement.md 业务需求、api.md 接口标准编写，统一制定测试环境、测试流程、测试用例、验收标准、异常测试、回归测试，用于完成项目全流程测试，发现 BUG 并修改重测直至全部用例通过。
2. 测试基础信息
2.1 测试环境
运行环境：本地开发环境
数据存储：内存全局字典 user_container
测试依据：严格对齐接口参数、校验规则、返回格式
测试类型：功能测试、边界测试、异常输入测试、流程联动测试
2.2 测试前置条件
已初始化空全局用户容器
所有 API 函数已按照 api.md 伪代码完整实现
通用参数校验函数全部正常可用
无前置脏数据，每次独立测试可清空容器
2.3 测试执行流程
清空测试数据，初始化环境
按模块顺序执行测试用例
记录实际结果，对比预期结果
不一致则判定缺陷，修改代码
修改完成重新执行失败用例
全部用例通过，测试结束
3. 通用测试规则
所有接口返回必须统一格式：status/message/data
所有输入必须先走参数合法性校验
边界值、空值、非法类型、越界数值必须全覆盖
操作联动顺序：新增 → 查询 → 修改 → 删除
失败用例优先修复，再执行正常流程用例

5. 联动流程集成测试
流程 1：新增用户 → 查询验证 → 修改信息 → 查询确认修改 → 删除用户 → 查询确认删除
流程 2：批量新增 → 全量查询 → 批量删除 → 清空校验
流程 3：连续多次非法操作，校验系统不会崩溃、数据不乱码
6. 异常容错测试
传入字符串类型数字 ID
传入空字符串用户名
年龄传入字符串非数字
连续高频调用接口无数据错乱
修改后再次重复修改相同数据正常兼容
7. 缺陷处理规范
测试结果与预期不一致 → 记录 BUG
对照 api.md 伪代码核对逻辑错误
对照 requirement.md 核对业务规则错误
修改代码后重新执行全部失败用例
同一问题连续两次未修复，重新梳理接口逻辑
8. 测试通过验收标准
所有单条功能用例 100% 通过
全部集成业务流程运行顺畅
所有异常输入均有合理拦截与提示
数据增删改查状态完全一致
接口返回格式统一无错乱
无程序报错、死循环、数据残留问题
9. 测试收尾
所有测试完成后整理测试结果文档，标注通过用例、修复记录、最终运行状态，完成 SPEC 全流程开发闭环。
