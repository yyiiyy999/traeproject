# 文档质量检查规范 (Quality Checklist)

## 4.1 三级检查体系

### 一级：完整性检查 (Completeness) - 每项15分，共75分
- [ ] 标题是否包含《哈姆雷特》与软件工程学习的关键词？
- [ ] 导语能否独立成篇？（不看正文是否完整理解写作意图）
- [ ] 四大主题章节是否都包含"文学情节→技术映射→个人经历→反思小结"四步？
- [ ] 总结是否回应了导语中提出的跨学科思考问题？
- [ ] 是否有具体的课程名、项目名、场景描述？（避免泛化）

### 二级：一致性检查 (Consistency) - 每项10分，共50分
- [ ] 术语全文统一（如前文用"代码审查"，后文不能用"代码评审"指同一概念）
- [ ] 四大主题与四大领域的映射关系是否清晰稳定？
- [ ] 时态统一（回忆阅读用过去时，联系当下用现在时，展望未来用将来时）
- [ ] 人称统一（主要用"我"，避免"我们软件工程学生"的泛化表述）
- [ ] 标点规范（中文正文用全角标点，英文术语保留半角括号）

### 三级：有效性检查 (Effectiveness) - 每项5分，共25分
- [ ] 每章删除测试：删除该章是否损害整体理解？如否，则该章冗余
- [ ] 反向阅读测试：从总结倒推，四大主题是否都有足够支撑？
- [ ] 跨学科测试：是否同时涉及文学情节与技术实践？（避免单方面偏题）
- [ ] 个人化测试：是否有足够的"我"的具体经历？（避免泛化空洞）
- [ ] 行动导向测试：读者读完后能采取什么具体行动？（如"下次遇到技术选型时，我会..."）

## 4.2 题材特化检查项

| 题材 | 特化检查项 |
|-----|----------|
| 读书心得（本篇） | 文学引用占比：是否过度引用沦为摘抄？（应≤30%）<br>个人思考占比：感想是否依附于具体文本？（应≥50%）<br>跨学科映射：文学与技术的类比是否合理且有深度？（避免简单粗暴） |

## 4.3 评分与迭代机制
- **基线分**：满分100，一级检查每项15分，二级每项10分，三级每项5分
- **通过标准**：≥85分可输出；70-85分需标注待改进项；<70分重写
- **迭代指令**：若未通过，使用"基于[具体检查项]的反馈，请修正[具体位置]，要求[具体标准]"

## 4.4 常见失败模式 (Anti-patterns)

| 模式名称 | 症状 | 修复策略 |
|---------|------|---------|
| 文学偏题 | 大段分析哈姆雷特的人物形象，无技术映射 | 强制每段文学情节后紧跟技术类比 |
| 技术偏题 | 大段讨论软件工程理论，无文学支撑 | 强制每个技术概念前先引用《哈姆雷特》情节 |
| 泛化空洞 | "我们要努力学习"、"哈姆雷特教会我们..." | 加入具体课程名、项目名、个人经历 |
| 简单类比 | "哈姆雷特像Bug一样"而无深度思考 | 深化类比，探讨"犹豫的价值"、"复仇的正义"等 |
| 头重脚轻 | 导语写800字，总结写200字 | 强制总结区字数≥导语区×0.8 |
| 概念通货膨胀 | 堆砌"微服务"、"敏捷"、"重构"等术语而无实质内容 | 每个术语必须跟"也就是说..."的解释句或个人经历 |
| 情感透支 | 形容词密度>25%（"非常"、"极其"、"深刻"） | 将所有"非常/极其/深刻"替换为具体程度副词或数据 |
| 正确的废话 | "我们要重视代码质量" | 加入主语、时间、衡量标准："我在数据结构课程中，通过单元测试确保了..." |
| 逻辑跳跃 | "因为哈姆雷特犹豫，所以我们要快速决策" | 强制补充中间环节，或使用"这意味着..."过渡 |

## 4.5 特殊检查项：跨学科写作

### 文学-技术映射质量检查
- [ ] 是否有"文学→技术"的双向映射？（避免单向投射）
- [ ] 类比是否合理？（如"犹豫≠拖延"，而是"深思熟虑的价值"）
- [ ] 是否有深度思考？（如"复仇的正义"与"代码质量的底线"的伦理关联）
- [ ] 是否有个人经历支撑？（避免纯理论讨论）

### 个人化表达质量检查
- [ ] 是否有具体的课程名？（如"数据结构"、"软件工程导论"）
- [ ] 是否有具体的项目名？（如"学生管理系统"、"图书借阅系统"）
- [ ] 是否有具体的场景描述？（如"在实现红黑树删除操作时..."）
- [ ] 是否有真实的情感表达？（如"这让我陷入了与哈姆雷特类似的纠结..."）

### 语气风格质量检查
- [ ] 是否使用了网络流行语？（如"绝绝子"、"yyds"、"emo"）
- [ ] 是否过度学术化？（如"综上所述"、"笔者"）
- [ ] 是否过度谦虚？（如"才疏学浅"超过一次）
- [ ] 是否有足够的"我"的个人表述？（避免"我们软件工程学生"的泛化）

## 4.6 最终输出检查清单
- [ ] 总字数是否达到3000字以上？
- [ ] 四大主题章节是否都完整？
- [ ] 每个章节是否都有"文学→技术→个人→反思"四步？
- [ ] 是否有至少4个具体的课程或项目经历？
- [ ] 是否有具体的行动转化计划？
- [ ] 是否符合"真诚个人化"的语气风格？
- [ ] 是否避免了泛化、空洞、简单类比等问题？
