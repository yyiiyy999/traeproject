# 主题锚定规范 (Topic Anchoring)

## 1.1 核心主题声明
- **主命题**：以《哈姆雷特》中犹豫与决策、复仇与正义、人性与伪装、命运与选择四大主题为镜鉴，反思软件工程专业学习中的系统设计、团队协作、代码质量与职业发展，探索文学经典对技术实践的启示意义
- **边界范围**：
  - 必须涵盖：
    1. 哈姆雷特的犹豫不决与软件工程中的技术决策、代码重构的类比
    2. 复仇主题与代码审查、Bug追踪、质量保证的关联
    3. 人性伪装与需求分析、团队沟通的映射
    4. 命运选择与架构设计、职业规划的对照
  - 明确排除：
    1. 不进行《哈姆雷特》的纯文学分析或学术研究
    2. 不讨论莎士比亚的生平或戏剧史背景
    3. 不堆砌软件工程术语而无文学支撑
- **目标读者**：大学课程老师，需要展示跨学科思考能力、个人学习反思与专业成长轨迹

## 1.2 偏题检测机制
生成过程中，每完成一个章节需自检：
- [ ] 本节内容是否同时涉及《哈姆雷特》情节与软件工程实践？
- [ ] 是否有"文学→技术"或"技术→文学"的双向映射？
- [ ] 若删除本节，"文学启示技术"的主线是否仍然完整？
- [ ] 本节是否引入了与四大主题无关的新话题？

## 1.3 题材适配示例
| 题材类型 | 主命题示例 | 边界排除示例 |
|---------|-----------|------------|
| 读书心得（本篇） | 《哈姆雷特》的犹豫、复仇、伪装、命运如何启示软件工程决策、质量、沟通、职业 | 不分析哈姆雷特的精神病理学、不讨论莎士比亚的语言艺术、不对比其他复仇剧 |

## 1.4 纠偏触发词
当内容偏离时，使用以下句式强制回归：
"回到核心命题：将《哈姆雷特》的[具体主题]映射到软件工程的[具体领域]，我们需要聚焦于..."
